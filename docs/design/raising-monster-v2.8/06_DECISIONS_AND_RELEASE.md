# v2.8 决策冻结与发布门槛

## 用户已确认，不得自行推翻

- DEC-A 四个 Tab 为 `今天 / 手帐 / 目录 / 记录`，手帐可选；四个标签保留 IP 形象和明确文字。
- DEC-B 双怪兽、深浅主题、成长地图、贴纸、原绘本插画与完整人物构图保留。
- DEC-C 不擅自减少角色使用量，不把 IP tab 改普通线性图标。
- DEC-D 观察/阅读、活动、健康记录是不同数据语义；接种与儿保不能由批量补看确认。
- DEC-E Android/iOS 共用产品体验标准，符合两端系统交互习惯；原有 47 屏合法功能必须覆盖。

## 发布准入门槛（由人工复核 + gate_check 联合执行）

**P0：出现任何一项则必须阻断发布。** 包括数据丢失、历史语义被更改、批量接种误确认、计时重复或失真、未保存假反馈、儿童隐私泄露、安全提示消失、核心操作被遮挡或完全无法返回。

**P1：完成双端针对性测试后才可作为正式发布候选。** 包括月龄切换正确性、定位/返回滚动、IP 标签可理解与易点、键盘/安全区、字体放大、手势冲突、TalkBack/VoiceOver 关键路径、不卡顿的计时和输入、深浅模式可读性。

**P2：可以排后但不能隐去。** 包括局部纹理、次要阴影、轻微图标风格、非核心插画修饰；需在遗留清单中明确版本计划。

**证据等级**：`R=发布报告声明`，`S=可见界面截图/录屏`，`C=代码与自动化日志`，`D=真机操作与环境测量`，`U=未知`。相互不能替换。

**门禁脚本限制**：只能检查矩阵完整性、状态/证据路径一致性；截图不证明保存逻辑或计时准确。人工需检查每项证据与实际预期一致。没有真机，就不得在双端真机状态打勾。

**发版审批**：Claude 输出`候选构建`与`发布建议`，实际发布动作需要现有权限与用户明确授权；构建成功不构成“已发布”。
