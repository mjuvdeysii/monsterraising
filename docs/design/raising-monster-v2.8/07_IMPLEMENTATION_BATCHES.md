# 分批工作与“漏做追责”流程

## 每批固定记录模板

- 批次：B0/1/2/3/4/5；仓库 HEAD / 基线版本 / feature branch / build hash。
- `范围`：Req_ID、Screen_ID、Test_ID、Android/iOS；改变的**具体文件**、原始行为与新行为。
- `功能映射`：每一项入口所在位置、操作结果、失败恢复、退出去向；涉及的历史数据含义与迁移方式。
- `视觉样本`：前后相同设备宽度+字体+主题+内容记录的截图；IP、完整插画、夜间模式分别有样本。
- `证据`：测试命令与输出、实际录屏、帧数据、屏幕阅读器结果；失败与未测项目单独呈现。
- `审计结论`：已验证 / 已实现待测 / 未实现 / 阻塞 / 待决策，任何缺项都不能自动改为已完成。
- `回滚路径`：提交 SHA、受影响模块、数据迁移可否撤回、未完成的问题归属与下一轮计划。

## B0：事实基线和规范差距

映射 47 屏、发布报告中的 2.6.52 项、初步发现的硬编码、IP 素材与双平台桥接。必须生成差距表；没有代码入口的需求标记 `待定位`，而非“页面不存在”。

## B1：基础样式与统一组件

建立/校对语义颜色、字号、字号缩放、间距、角半径、IP 标签与 Button/Sheet/Toast 状态。验证触控目标、焦点、禁用和按压，检查深浅 × 双角色组合；组件已存在且合理则复用。

## B2：最核心浏览路径

A1 今天 → C1 月龄导航 → C6 月龄页 → C7–C9 活动详情 → 操作确认 → 来源返回；连带 A4 批量语义、C2 地图定位。导出操作路径录屏和快速切月压力用例。保留真实各类数据。

## B3：手帐、计时、记录安全

B1–B15 快捷操作与计时，D1–D7 记录/贴纸/恢复；分别测 Android/iOS 进入后台/系统杀进程/断网、重复提交、精确保存与失败恢复。按真实持久化回执报告“已存到本机”。

## B4：阅读和趣味精修、原生感验收

完整插画、绘本字号与留白、IP 反馈与主题切换、键盘焦点、系统手势、图片加载、动画中打断与滚动长列表；用 Android Perfetto / iOS Instruments 真机记录，不虚报流畅度。对照 Web 版做主任务效率比较。

## B5：品牌候选评审 / 发布

先出 A/B/C 中英文品牌完整触点对照，**等待用户批准**；品牌批次不得阻断已审查完的非品牌功能。最终先跑双方构建 + P0/P1 QA + `--mode release`，再出候选版说明。无法完成真机或商店步骤则维持“待设备/平台验收”。

## 每轮催办机制（Claude 自检）

1. 更新 `04_REQUIREMENTS.csv` 的所有受影响 Req_ID，不接受只改代码不更新台账。
2. 核对 47 屏中被此次改动影响的全部子页面；扫描所有未关闭 P0/P1 并单独报告。
3. 运行 `--mode audit`；如存在缺口则在最终回复**先给未完成项**，下一轮从这些项目继续。
4. 不把 `待决策`、`未执行`、`已实现待测`、`无法验证`转换为通过。不得因工期省略被要求的验收。
5. 重复出现在两个批次的遗漏项必须标成 `反复遗漏`，列出阻塞依赖和可执行修复动作。
