# 养小怪兽 Raising Monster｜产品体验与跨平台设计精修规范 v2.7

**定位**：0–36 个月蒙氏早教内容 + 育儿手帐；家长/照护者使用，儿童绘本编辑设计（Editorial Kids' Picture Book）与成熟移动端工具体验结合。  
**版本**：设计指南 v2.7，2026-10-19。**适配基线**：用户提供《全览.pdf》（Android v2.5.51，47 屏）及 Claude 对 v2.6.52 的发布报告。  
**证据边界**：本指南**未读取 v2.6.52 的源代码、二进制或真机录屏**；“已实现”仅代表 Claude 的发布声明，尚不能据此断言实际交互已通过设备验收。  
**实施对象**：正在开发的 Android 与 iOS 客户端（据发布报告为网页内核 + 原生外壳；具体 WebView/bridge/navigation 技术需先核查仓库）。

## 0. 不可覆盖的现有产品决策

1. 保留 **今天 / 手帐 / 目录 / 记录** 四个一级入口；手帐为可选功能，关闭时按现有产品逻辑处理入口和说明，不擅自替代。
2. 保留 **双小怪兽 IP、IP 化底部标签、贴纸册、绘本成长地图、深色主题和两套形象切换**。禁止未经确认改成纯线性图标、消除角色或重新命名已存在的功能。
3. 保留 47 屏的全部功能与合法数据：亲喂、睡眠、瓶喂、尿布、维生素、辅食、洗澡、早教、体温、生长、备注、接种/儿保、观察清单、主题内容、收藏、导出、备份与设置等，以实际仓库为准。
4. 活动做过、观察清单、内容看过、接种/儿保、手帐事件、贴纸纪念必须是独立语义；任何“批量补看”不可自动更改接种或儿保完成状态，且不得把阅读内容或参与活动写成能力达标。
5. 视觉保留奶油白背景、绘本实景/蒙氏活动插画和角色大形象；图像被裁切时优先修正容器比例、响应式位置与内容流，而非盲目压缩高度。
6. 所有真机/辅助功能/性能结论必须附可验证证据。模拟器构建通过 ≠ iOS 交互通过 ≠ App Store 审核通过。

## 2. 信息架构及出入口契约

### 2.1 四层组织
- **L1 首页任务**：今天要看的要点、可继续的事情、明确行动。
- **L2 检索与导航**：月龄选择、主题、目录、手帐日期、搜索、收藏。
- **L3 操作/阅读详情**：活动步骤、材料、安全、观察、育儿记录、计时。
- **L4 依据和管理**：CDC 等来源、说明、备份/导出/权限/隐私。

避免把 L4 大段内容平铺进 L1；详情必须有来源入口，安全警示仍在 L3 可见。每个显式入口必须有明确目标与返回目标；深链与跨 Tab 跳转需保存来源。

### 2.2 “进入—操作—出口—返回”统一约定
| 进入点 | 操作目标 | 成功状态 | 退出与返回目标 | 中途退出 |
|---|---|---|---|---|
| 今天推荐 | 阅读活动、记为做过 | 同步状态文字 + 撤销 | 回到今天推荐的原位置 | 无提交则无完成值 |
| 今天继续 | 恢复计时或上次阅读段落 | 计时状态/阅读位置一致 | 回到今天 | 保留正在进行的会话 |
| 目录全部月份 | 找到任意 0–36 月 | 顶部显示“正在看 X 月” | 返回上次目录定位 | 关闭 Sheet 保留浏览月龄 |
| 成长地图 | 定位当前或历史月份 | 路线对应卡片可见、标题一致 | 地图原滚动位置 | 不重置浏览上下文 |
| 活动 → 记录 | 记录活动执行 | 与当次活动 ID 关联的真实记录 | 返回原活动和月份 | 草稿恢复 |
| 手帐快捷记 | 记录护理事件 | 已存本机/等待同步按事实显示 | 返回这一天，保持日期 | 未完成内容保留 |
| 记录进度 | 查看观察/活动/健康 | 每类分子/分母与日期口径可见 | 返回“记录”所在 Tab | 不改变记录状态 |

### 2.3 一致的交互深度
- 访问**当前**月龄，从“今天”单次明确操作应直达；从“目录”可见“回到现在”。
- 访问任意历史月龄，从“目录”通过“全部月份 → 月份格”一般不超过两个明确选择动作（不将关闭、可选筛选计入）。
- 常用“新建一条简易手帐”以 20–60 秒作为**待用户测试的体验目标**，不能据此凭空声称达成。
- “继续上次”打开的必须是**真实可恢复**内容；如果没有可恢复对象，整块换成合适的独立入口，避免灰掉的空控件。
- 每层页面应有稳定的后退方式：回原 Tab、原选择、原列表位置与原草稿，而非一律回首页。

## 3. 页面级精修说明（保留现有业务）

### A1 今天：首屏与阅读顺序
**理想次序**：安全区与品牌识别 → 月龄信息（当前天数、参考阶段） → 今日建议**一张**主卡（活动插画、标题、必要安全提示、`看做法`、`换一个`） → `继续上次`（有可恢复对象才出现） → 高频入口 `记一条` 与 `看本月` → `更多工具` → 接种/儿保、睡眠与附属信息。

- 6 宫格降级后不能产生“隐藏功能消失”的问题。“更多工具”展开后保留接种儿保、补看、成长地图、搜索、全书结构，入口文案与原数据对应。
- 今日推荐需要允许**换一个/今天先不做**。无推荐时表现为“本月活动”入口，不制造“未完成”压力。
- 如正在计时，`继续上次`必须显示计时类型、运行中/已暂停和目标操作；若仅有历史阅读，显示最后阅读的章节及简短定位。
- 小怪兽应融入月龄卡或今日推荐主图，原插画比例优先，文字和 CTA 位于独立阅读表面；不得通过压扁画面制造空间。
- 首屏不得被全页滚动阻断；功能标题和可点击内容必须可识别，避免大面积同强度边框卡。

**建议低保真布局**（不代表代码已存在）：
```text
[养小怪兽  IP标识                       搜索/设置]
[宝宝现在 3个月17天]    [看本月]
[完整比例的绘本插画 / 随容器响应调整]
[今天可以做]   [换一个]
[活动名称 + 一句做法概述]
[安全提醒（如存在）]
[看做法（主要）]       [今天先跳过]
[继续上次：上次章节或正在计时的事件]
[记一条]              [更多工具]
[IP今天] [IP手帐] [IP目录] [IP记录]
```

### A4 首次补录：文字必须支持真实状态
- 标题建议“补看前几个月的内容”；提示“批量标记只更新内容浏览状态，接种与儿保请对照实际记录逐项确认”。
- 观察内容使用`标为看过`或`已阅读`，**不得**反写为`已观察到孩子出现该行为`。
- 活动若只是家长浏览，使用`标为看过`；若确曾开展，则提供显式`标为做过`单独确认。旧版“全部勾上”若混合两类状态，先迁移区分再上线，不得默默改历史含义。
- 危险操作展示影响数量与范围（如“标记 12 条内容已看过”），允许撤销；弹层关闭不会提交尚未确认项目。
- 接种记录应有`记录日期/产品或事项/来源与备注`等现有合法字段，医疗状态不属于批量补录。

### C1 月龄选择：先定位后浏览
**顶部轻量带**（5 个月上下文，即 ±2）：`4月 5月 [6月 · 正在看] 7月 8月 [全部月份]`，旁侧文字`宝宝现在 6 月`。当前月龄与浏览月龄相等时可以合并说明，不重复挤在数字上。

- `[全部月份]` 开启 Sheet，按区间分组覆盖 0–36 共 37 个独立月份。交界月不能重复或丢失。
- 每个月份格有明确 `X 月`、是否为“现在”、是否“正在看”；如显示进度，需说明该进度属于哪类事项。无传达价值的圆点取消。
- 连续快速选择 2→12→5 只显示最终 5 月内容；标题、主图、事项、完成状态的同一个 month ID 原子更新；异步旧结果丢弃。
- 数字栅格可在 Sheet 里存在，但不要把所有 37 格直接压到今天首页。

### C2 成长地图：保留亲子叙事价值
- 保留弯曲成长路径、月龄插画、路径节点和小怪兽；它承担**浏览探索**，与效率型选择器共存。
- 固定/浮动`跳到当前月龄`只在有实际跳转意义时显示，激活后目标节点可见，并用短暂描边或底色标出；减少动画开启时直接定位。
- 不使用闪烁放大或路线无限自动滚动；滚动位置保存至返回栈；从地图选月龄后返回应回到原地图位置。
- 路径上的空白“未来月份”不得表现成儿童发展落后；里程碑文字应保持发展差异边界。

### C6 月龄页：读者先理解当前所处阶段
顺序：`月龄标题` → 小字状态`宝宝现在 X / 正在浏览 Y` → 绘本原画（不裁角色脸、头饰或重要材料） → 本月关注摘要 → 六个领域 → 本月活动 → 接种/儿保 → 本月手帐/附录与来源。

- 月龄跨度和满月龄日期从同一权威出生日期/日历计算函数获取，不允许手写示意值混入真实产品。
- 标题只出现一次；长中文描述单列、左对齐；领域卡一眼看出类别与是否可点击。
- 顶部插画：优先 `contain`/自然高度（保持原长宽比）；如果展示区必须裁切，需**逐资产定义安全裁切区**，禁止统一 center-crop；深色素材另测。
- 接种/儿保直接区分建议时间与真实完成记录；重要安全提示不藏于折叠区底部。

### C7–C9 观察 / 活动 / 健康
| 类型 | 允许的操作文字 | 禁止自动推断 | 推荐反馈 |
|---|---|---|---|
| 观察清单（内容阅读） | 查看说明、标为看过 | 已出现该发育能力 | “已标为看过 · 撤销” |
| 观察事实记录（如有） | 记录观察结果 | 临床评估/诊断结论 | “观察记录已保存” |
| 早教活动 | 查看做法、记为做过 | 发展达标 | “本月记为做过 · 撤销” |
| 接种/儿保 | 查看建议、记录真实事项 | 已接种/已检查 | “待确认 / 已记录（日期）” |

- 活动完成后的撤销应避免短时 toast 消失即无处修改：至少在活动详情再次操作可更正；展示记录日期与本月归属。
- 计数器变化必须与对应数据表的一致事务/同步结果绑定；不可拿整体“本月进度”代表孩子能力或健康水平。
- 有安全风险的活动把材料尺寸、监护与警示呈现在开始操作之前；医学信息不得由设计改造自动重写。

### B1 / B2–B4 手帐与计时
- B1 主要展示**最常用快捷记录 + 本日最近事件**；原有类型继续保留在“更多/其他”或可展开分类，不擅自删除。
- 亲喂：先选左右后启动；睡眠：明确“开始/暂停/结束”；活动中状态足够大，夜间单手可操作，防误碰结束。
- **一个事件的生命周期**：`idle → running → paused → running → finished(saved)`；异常恢复可进入`needs_review`，不得把不确定的时长直接当作已完成的精确记录。
- 计时显示以持久化的开始/暂停/恢复时间点为基础重算，避免依赖页面存活时的 `setInterval` 计数；系统时间手动修改、进程重启、跨日和跨时区要验证处理策略。
- 防重：点击两次“结束”仅生成一个 event ID；从小组件与 App 进入的同一计时器必须争用同一状态源；返回后台重新同步只刷新状态，不新增记录。
- 成功反馈区分`已存到本机`、`等待同步`、`云端已同步`、`保存失败`。只有真实写入持久层成功才显示第一项；同步机制不存在时隐藏云状态。
- 失败保留原输入，允许重试或复制草稿；进度圆环与统计不得先写假结果。

### B6–B15 辅助记录与夜间模式
- 补录日期和事件日期分开；时区及跨午夜记录按实际发生时区处理。时间线修改/删除提供撤销或可理解的确认。
- 夜间模式（B13）保持**专用于夜间护理的低眩光、大点击目标**，与全 App 深色外观模式分离（若原产品已有独立能力）。
- 给医生看的摘要（B14）包含计量单位、区间、缺失项说明；导出/分享前预览，不附加不必要的儿童隐私字段。
- 未开启手帐的 B15 使用清楚的功能解释与显式开启入口，不借由奖励机制催促开启。

### D1–D7 记录、纪念与设置
- D1 推荐顺序：最近操作/记录 → 本月观察、活动、接种儿保**分开统计** → 收藏与快速查看 → 贴纸纪念 → 设置帮助入口。
- 统计同时提供分子、分母、时间范围与“记录含义”，例如“本月活动做过 6/22”，避免把三类状态合成有歧义的总完成率。
- D2 补看过往按 A4 语义；D3 收藏保持筛选/返回位置；D4/D5 设置的行项目可扫读、说明就近。
- D6 形象切换：保留两套怪兽主题与所有 IP 标签，切换后不清空当前月份、表单、记录和阅读位置；主题色必须保持操作色语义可读。
- D1 贴纸是**成长纪念**，不关联同龄排名、连续签到惩罚或育儿绩效；已取得的贴纸保持兼容，不用重算抹除。

### C3–C5、C10–C13 与 A2/A3/A5/A6
- **主题/活动库/搜索**：搜索结果按活动/观察/接种儿保/专题展示清楚的内容类型标签；已有筛选状态返回恢复，历史阅读保留位置。
- **说明与来源**：内容引用不挤在主文末尾，正文必要条件与安全判断就近显示，完整参考资料进入 L4。
- **出生日期未设置**：A5 不造“宝宝现在”假日期；允许查看通用内容，基于生日的个性化入口给出设置原因。
- **首次须知**：A6 高优先级安全/隐私说明可感知并可重读，避免冗长一次性强制连续弹窗。
- **手帐月度/生长图表**：参考值与真实记录区分；曲线轴单位明确，缺失点不插值成观测事实。

## 4. Kids' Picture Book 的视觉与阅读设计

### 4.1 视觉原则
- “柔和背景 + 真实可辨的绘本插画 + 强层级文字 + 可识别操作”。童趣来自叙事、角色、插画材料，不靠全屏漂浮动画和糖果式状态色。
- **插画/文字分层**：主图具有留白、比例与情节；关键操作文本都应是真实渲染文字，便于缩放/朗读/选中。
- 在单页中让一个插画或一组角色成为情感主焦点；其它位置仍可按需要使用小怪兽作为功能识别。**不设置强制削减 IP 数量的配额**。
- 同级分类使用一致图标语法、颜色明确语义；类别色不直接充当危险或主操作色。

### 4.2 文本角色（项目起点，需真机字体缩放核验）
| 角色 | 建议基准字号/行高 | 职责 |
|---|---|---|
| `displayStory` | 28–32 / 36–40 | 绘本封面、大月龄视觉标题；低频使用 |
| `pageTitle` | 23–24 / 30–32 | 页面名称 |
| `sectionTitle` | 19–20 / 27–29 | 模块分组 |
| `cardTitle` | 17–18 / 25–27 | 卡片/活动名称 |
| `body` | 16–17 / 25–28 | 实际操作、步骤、长阅读；建议长段默认 17 |
| `support` | 14–15 / 21–23 | 概述和操作附注 |
| `caption` | 12–13 / 18–20 | 非必要的次级日期等；医疗与安全提示不得用此档 |
| `button` | 16–17 / 22–25 | 行动文字 |

- **字体配置**：中文功能/正文优先系统 sans（iOS 系统中文/Android 系统中文或 Noto Sans SC 回退）；少量绘本章标题可测试 **霞鹜文楷**；英文品牌/大数字可测试 Nunito。真正投产需校验字体许可、文件体积、iOS 载入及中英混排表现。不得将系统 SF 字体文件私自打包分发。
- 正文左对齐；居中用于不超过两行的封面说明或纪念文案。**一句核心含义优先 1–3 行**，长段按信息自然分段；不可用双列装入活动步骤。
- 小屏与系统大字时卡片增高，行距随字体调整，不缩小至 12px 挤回原高度；读屏焦点顺序与视觉顺序一致。

### 4.3 网格、间距与容器
- 间距 token：`4/8/12/16/20/24/32/40/48/64`；同段 4–8，同组 8–12，卡片内部 16–20，跨模块 24–32；页面侧边 16（窄）或 20（常规）。
- 圆角：`8`小标记，`12`按钮/输入，`16`卡片，`20`弹层/大型绘本卡。需要贴纸的特殊轮廓只作用于装饰层，点击热区仍清晰。
- 同类卡片统一主图比例、字段顺序和 CTA 位置；阅读正文保持单列，按钮/状态组合优先避免右侧窄列长文。
- 卡片阴影仅分层、无需厚重投影；通过标题与留白先建立区分，避免“全部都有描边”；长列表可以用行分隔代替一层套一层的卡片。
- 图像先占位、再解码；原有“头顶被裁”的场景须检查图片 alpha 留白、容器高度、`object-fit`, `object-position`, border-radius clipping 与不同屏宽下的文字换行。

### 4.4 保留全局 IP 标签系统
- 四个一级入口均可采用同一世界观的 **怪兽角色姿态/物件图**；已选态至少同时体现 `角色变化（若有）+ 背景/描边+中文标签` 中两种，未选态也可辨识。
- 标签图像**不得是没有文字的唯一导航说明**；即便四个 IP 造型互相相近，中文标签保持清晰可读。
- 建议按标识绘制专用“小尺寸 tab 版”素材，而不是把 500px 全身插画缩成 24px；关键眼睛、手持物及头饰在实际图标尺寸必须完整可辨。
- 已选态不改变按钮尺寸/位置，切换形象不影响 tab 的触控面积、scroll position、route stack 或状态。
- 两套主题 × 浅/深色的 tab、章节插画、贴纸与空状态逐一截图检验；正式命名/主色继续保持待确认，不捏造最终色板。

## 5. 精细交互规范与动效

### 5.1 触控、滚动和跟手
- Android 触控区域**项目按 48×48dp 及以上**；iOS **项目按推荐的 44×44pt 及以上**；WebView 内的 CSS 像素要结合实际 viewport/系统缩放验证，不能把 CSS px 当原生 pt/dp。
- 手指拖动列表/抽屉时尽量 1:1 跟随；松手后才出现惯性/回弹。系统滚动优先，不重写惯性引擎。
- Sheet 可下拉时，不与列表滚动、系统边缘返回争抢手势；内容未保存时不能默默关闭造成数据丢失。
- 点击必须即时有**可见按下反馈**，业务完成后的成功提示延迟到真实提交完成；重复点按不重复创建记录。
- 可触控图标容器可以大于可见插画，视觉图形不会因扩大热区变得臃肿。

### 5.2 初始 Motion Tokens（均为项目建议，非 Apple/Google 强制值）
| 类型 | 初始时长 | 例子 | 动作要求 |
|---|---:|---|---|
| `press` | 80–150ms | 按下/释放 | 即时启动，不等 API |
| `toggle` | 120–180ms | 收藏/勾选 | 无大幅弹跳 |
| `monthSwitch` | 180–240ms | 月龄切换 | 内容 ID 同步、旧动画可取消 |
| `navigation` | 220–300ms | 进入/退出详情 | 优先平台原生过渡 |
| `sheet` | 原生；自定义 240–360ms | 全部月份/操作选择 | 拖动跟手，释放后吸附 |
| `monsterJoy` | 300–550ms | 真实完成后的角色微动作 | 不遮挡点击，最多一次，可停用 |

- 60Hz/120Hz 的约 16.7ms/8.3ms 是显示帧时长参考，不代表实际产品已达成。使用 Chrome Performance/Android Perfetto 或 FrameTimeline、iOS Instruments 和真机高帧录制判定卡顿源头。
- `prefers-reduced-motion` 与平台桥接的 Reduce Motion/系统动画偏好应一致；减少动画开启时，采用静态状态变化、简短淡入而非跟随式大位移。
- 异步返回时，同屏旧请求不能覆盖新状态；展示层应使用统一 request/version ID 或取消机制。首次图片出现不改变卡片高度。

### 5.3 小怪兽的趣味设计细则
- **品牌出场**：页面封面、主题切换、纪念节点可有主要角色插画。
- **流程参与**：活动完成后小怪兽做短动作、贴纸轻微盖章、月龄跳转给出动作目标的视觉反馈。
- **用户安静区**：夜间计时、手帐输入、医学信息、安全警示期间，角色可作为静态标记，但不循环播放、挡住输入或抢占读屏焦点。
- **两套主题**：在功能行为一致的前提下允许角色动作风格不同，需有共同 duration 与反馈语义。
- 不用“怪兽饿了”“连续未签到”等施压式反馈；贴纸用于纪念，不评价儿童发展进度。

## 6. 平台适配（同一套任务，分别尊重系统行为）

| 场景 | Android | iOS | 统一验收 |
|---|---|---|---|
| 底部四个 IP tab | 处理系统导航 inset、返回到正确栈、TalkBack | 处理 Safe Area/Home Indicator、VoiceOver、系统 Tab 语义 | 四个 IP + 中文标签；切换不丢原状态 |
| 返回 | 系统 back、predictive back（按框架能力） | 顶部返回 + 系统边缘滑返（框架支持） | 返回前一来源、弹层先闭合、计时继续 |
| Sheet | Material/原生手势能力可用时优先 | iOS 原生弹层逻辑可用时优先 | 下拉跟手；不会误提交/丢草稿 |
| 字号 | `sp`/系统放大或等效 WebView 桥接 | Dynamic Type/等效 text scaling bridge | 中文内容不裁切、可放大、按钮增高 |
| 状态栏/键盘 | Edge-to-edge + IME Insets | Safe Area + 键盘避让 | 首尾内容和 CTA 可达，不双重留白 |
| 读屏 | TalkBack | VoiceOver | tab 名称、按钮状态、操作结果均可朗读 |
| 减少动画 | 系统动画设置 | Reduce Motion | 动作可停用，任务能完成 |
| 夜间模式 | 系统/手帐夜间策略区分 | 同左 | 明暗、角色材质和对比均可读 |

**WebView + 原生外壳注意**：必须确认原生 Back 与 Web 历史栈的协调；外壳手势与 DOM 触控是否冲突；viewport 是否启用 safe-area；键盘弹出是否触发双重 padding；Web 字体缩放是否读到系统偏好；照片/导出/分享/通知等真实设备能力及离线体验。不要因为同一份 HTML 能运行就声称两端体验一致。

**iOS 商店准备**：Apple App Review Guideline 4.2 关注 App 是否具备超越简单网页包装的实际功能和适合 App 的交互。当前育儿手帐、计时、数据记录与离线体验可能提供真实效用，但仍需核查实际实现、权限流程与审核要求；不能承诺过审。

## 7. 视觉和内容一致性检查
- 颜色：canvas/surface/text/primaryAction/onPrimary/success/error/info/milestone 各自独立；两套 IP 允许换主题主色，但不可把代表错误和接种状态的颜色变成奖励色。
- 对比度：项目按普通正文 ≥4.5:1，大字 ≥3:1 检查；状态不可仅靠颜色区别，安全文字与正文同等可读。
- 内容：页面标题讲具体信息，操作按钮命名清楚，拒绝口号式表达、自问自答、先否定再肯定。
- 公共健康信息：保留来源、地区适用性与更新日期；任何开发改动不得无依据调整医疗、儿保建议。
- 隐私：儿童出生日期、健康事件、照片及家庭记录的备份/云共享/导出范围应明确；没有配置的云服务不得假装可用。

## 8. 验收方式与发布门槛

**必须依次完成**：仓库审计 → 47 屏映射 → 设计令牌梳理 → 主路径改善 → 手帐可靠性 → 双主题/双平台 → 真机 QA → 回归与发版。

- **P0 阻断**：接种/儿保被批量误勾；育儿记录丢失或重复；计时恢复产生错误事件；敏感儿童记录外泄；关键操作不能取消/返回；医疗/安全信息丢失。
- **P1 优先修复**：系统返回手势冲突；当前/浏览月龄错乱；字体放大裁切；按压延迟；恢复滚动错位；主流程不易找到；深色主题重要文本对比不足。
- **P2 可逐步精修**：卡片层级不足、插画裁切、标签间距不统一、角色反馈不自然、贴纸定位不佳。

**建议用户研究（未开展，不能填通过）**：5–8 名实际照护者完成“查看当前月龄活动、定位 12 个月内容、补录曾做活动、夜间计时、找回旧手帐”五项任务；记录成功率、操作次数、误触、任务时间、主观清晰度、是否理解“记录”和“发展达标”的区别。跟现有 v2.6.52 同流程对照。

完整可执行用例参见 `03_Acceptance_Test_Cases.csv`；页面范围参见 `04_47_Screen_Coverage.csv`；待确认项目参见 `05_Decision_Log_and_Release_Gates.md`。
