# Raising Monster v2.8｜设计规范增量与执行验收

本文与 `reference_v2.7/01_Raising_Monster_Design_Experience_v2.7.md` 共同生效。发生冲突时遵循：用户当前已确认决策 > 数据正确性/平台安全 > v2.8 明确增量 > v2.7 基线 > 设计案例参考。**美术参考不能替代真实产品功能。**

## 1. 全局 App 体验：每次操作都要有“入口—反馈—出口—恢复”

- 一级固定四 Tab：今天 / 手帐 / 目录 / 记录。四个 Tab 使用现有小怪兽 IP 素材与清晰文字；不能自动统一成普通线框图标，也不能擅自减少角色。
- 每个次级页面明确上级、返回目标、可能跳转对象和离开时需要保留的状态。跨 Tab 导航保留来源；Android back 优先关闭弹层/键盘后正确返回；iOS 优先符合系统导航返回与可中断边缘手势。
- 标签切换保留各自列表滚动、筛选、已选日期、浏览月龄和正在编辑的草稿；不会因为重新渲染把页面置顶。
- 关键业务过程应允许不依赖网络完成基本工作：本地手帐可输入和保存；网络不可用时诚实展示本地状态，恢复网络后明确同步（仅当实际实现同步）。
- 用测量而非感觉评价“像 App”：主任务操作次数、首次可用时间、输入响应、滚动连续、返回正确率、中断恢复成功率及误触次数，均在相同设备/数据/构建下对照。

## 2. 排版与信息分层

- **信息规则**：第一屏有明确主任务；每个区域一个主题。概览层给出阶段/摘要，正文层给行动细节，依据层给来源；接种安全前提不可移到折叠尾部。
- **字体规则**：中文正文 16–17 为建议起点，活动步骤优先 17；页面标题约 24、模块标题约 20、卡片标题约 18、辅助信息 14–15。安卓通过系统字体放大/等效桥接，iOS 通过 Dynamic Type/等效桥接真实校验；不要在布局有溢出时缩小正文来掩盖问题。
- **阅读感**：关键表单、健康/观察正文左对齐、自然换行、单列；插画和短标题构成绘本节奏。少量霞鹜文楷只用于叙事层候选；不把显示字体用于主控件。英文可测试 Nunito，但须过字号/字宽/授权核查。
- **间距规则**：`4,8,12,16,20,24,32,40,48` 的统一系统；屏幕两侧一般 16–20，卡片内约 16–20，模块间约 24–32；圆角 12（控制）/16（卡片）/20（弹层）。项目 token 是起点，不强制覆盖经过审查且有效的实现。
- **实际压缩**：优先删除重复标签、合并次要分组、降低装饰面积和减少嵌套容器；不得把完整插画直接裁头、把正文改为两列、让热区变小。

## 3. 指定屏幕的细腻要求

### A1 今天
- 视觉顺序：实际月龄/日期 → `今天可以做` 一张建议卡（插画、摘要、安全前提、看做法、换一个）→ 有状态才显示`继续上次`（计时/最近阅读）→ 快捷 `记一条`、`看本月` → 次要 `更多工具`。
- 不让完整大插画强占首屏：用固定宽度内的**自然比例**、插画独立容器和文本分层；以内容高度自适应保证主 CTA 易见，不以裁掉怪兽部位求紧凑。
- 页面顶部的日期、宝宝生日和月龄都由同一计算逻辑生成，避免演示数据污染真实状态；安全提醒不低对比。
- `换一个`和`今天先不做`都不可写进“已做”；`继续`在无历史时替换成真正有意义的入口。

### B 手帐（包括 B2–B4 计时）
- 页面先显示高频记录和最近事件，长尾功能以“其他”可展开；可选开关语义保留。
- 计时器必须从持久化起点计算、具有幂等结束；验证前后台、锁屏、系统杀进程、重启、调整系统时间/时区、Android/iOS 中断与小组件（如真实存在）。不确定记录显示“需要核对”，不得误显示“已保存”。
- 夜间模式的计时主控要足够大、有误触保护，和全局深色主题保持概念区别；所有记录有本机保存/待同步/失败真实对应状态。

### C1 月龄选择与 C2 成长地图
- 目录主导航采用 `当前月龄锚点` + `相邻 ±2` + `全部月份 Sheet`，Sheet 内按阶段分组覆盖 0–36 共 37 月。顶层去掉无法解释的圆点。
- `currentMonth`、`browsedMonth`、`progressByType` 属于独立状态，不以一个选中布尔值互相覆盖。快速 3→9→5 最终标题、绘图、事项与进度全为 5 月，不显示短暂旧内容。
- 成长地图保留绘本路径，用于探索；提供“跳到当前月龄”，返回时保留地图滚动、来源和定位。

### C6–C9 月龄内容
- 只出现一次主标题，明确“宝宝现在”和“正在浏览”差异；插画完整展示、字体层级比重复边框更突出内容。
- 阅读内容遵循：这个月的重点 → 六个领域 / 本月活动 → 健康事项 → 可记录与来源。活动详情采用 `做什么、需要什么、怎么做、观察什么、安全提示、记录`；关键安全前提在开始前可见。
- 浏览已看、活动实际做过、观察事实、接种儿保真实记录独立保存；“活动做过”不得推断孩子发展达标；健康事项永远逐项确认。

### D 记录与贴纸
- 最近操作/记录与收藏要容易找到；观察、活动、健康的计数各自带分子、分母与口径。贴纸放在纪念区并保持已拥有状态和双 IP 表情，避免把育儿变成连续签到任务。
- 搜索和收藏从列表到详情再返回，筛选词、排序、历史位置必须保留；空列表提供具体入口而非空泛怪兽图。

### E 主题与品牌
- 双眼/独眼 × 浅色/深色 × 四个 Tab 的完整状态图分别验证。名称更改需要单独审批；既有正文、角色图形、贴纸数据不应随着候选品牌更改。

## 4. Motion、触控、性能、无障碍

| 行为 | 项目起始指导 | 必须检验 |
|---|---|---|
| 触控目标 | Android ≥48×48dp；iOS ≥44×44pt 推荐；WebView CSS 像素不能直接视为原生单位 | 真机标定热区，Tab/小图标/危险操作都符合；不会串点 |
| 按压响应 | 立即在最近可见帧反馈，释放恢复约 100–150ms | 重复快速点击、网络等待、切页不中断业务状态 |
| 月龄切换 | 180–240ms，切换内容与选择状态同源 | 快速连续切换无旧响应覆盖；用户可中途反选 |
| 弹层/导航 | 平台原生优先，项目自定义起点 220–360ms | 系统返回/边缘手势/拖动冲突测试，弹层跟手 |
| 怪兽微反馈 | 局部一次性 300–550ms，系统减少动画时降级 | 护理、输入、医学阅读期间不遮挡、不循环干扰 |
| 滚动性能 | 目标尽可能稳定接近设备刷新率，60Hz 帧预算约 16.7ms、120Hz 约 8.3ms | Android Perfetto/FrameTimeline，iOS Instruments；报告 p95、卡顿帧与测试环境，不能空称 60fps |
| 字体与读屏 | 中文自然换行、TalkBack/VoiceOver 可达 | 大字、屏幕阅读器、减少动画、焦点恢复 |
| 弱网/离线 | 编辑可恢复，失败不假报成功 | 慢网重试、强退、无网络、存储容量不足、同步冲突 |

## 5. 设计稿交付要求

每一批的改版图必须与 **2.6.52 当前实际页面截图逐屏对应**，而非把旧版或 AI 脑补的业务当作真实页面。前后对照附路由、同样内容样本、相同设备尺寸、字号模式及主题；附三条判定：减少了哪些视觉搜索、保留了哪些原有功能、改动后入口从哪里进/哪里返回。

## 6. App Store / Play 真实应用体验

当前混合技术栈据发布报告为 WebView + 原生外壳，必须先看仓库。检查照片/相册、系统分享/导出、状态栏/安全区、通知权限、原生返回、后台计时和本地离线能力，保证原生平台的预期一致。iOS 的审核、隐私声明与儿童信息管理应基于实际数据采集和 SDK 事实准备；模拟器构建成功不能当上架合规证明。健康类提醒核对地域与来源，不暗示诊断。
