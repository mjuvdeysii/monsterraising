## 证据等级

- `R`｜发布报告自述（例如：2.6.52 构建通过）
- `S`｜截图/录屏可直接观察（但不证明底层数据或时序）
- `C`｜代码与测试结果证实（有文件、提交、命令）
- `D`｜真机设备实测（机型、OS、构建、复现路径与记录）
- `U`｜未验证/未知

同一要求有多个证据等级时分别标注，不以其中一种代替另一种。特别是：iOS 模拟器构建成功=构建层面的 C；不是交互性能的 D，也不等于 App Store 审核通过。

## 发布门槛

### P0（出现即停止发版）
- 旧记录被迁移后静默改变语义、缺失或重复。
- A4 接种/儿保自动勾选或活动被默默写为孩子能力达标。
- 计时恢复错误导致无依据时长、同一事件重复完成或未保存仍显示“已保存”。
- 安全/医疗说明丢失，隐私数据泄漏，用户草稿被无提示销毁。
- 退出/返回无法正常操作，系统层出现关键触控死区。

### P1（应修复并完成双平台针对性验收）
- 当前月龄/浏览月龄混乱；异步旧请求覆盖新月份。
- 原导航来源/筛选/滚动位置无法恢复；IP tab 识别困难。
- 字体放大截断、读屏主要按钮缺语义、键盘遮挡 CTA。
- 关键交互明显卡顿、手势不跟手或动画无法中断。

### P2（迭代精修）
- 同级组件间距/圆角细微不一致；贴纸陈列密度欠佳。
- 角色完成微动效过长；插画局部多余留白（但不影响可读）。

至少覆盖：一台低/中端 Android、一台高刷 Android（如有）、一台较小屏 iPhone、当前主力 iPhone；测试系统字号正常/较大/无障碍大字、浅/深模式、两套小怪兽、离线与弱网。数量为建议覆盖，并非平台官方硬性指标。每个“通过”必须可复查。
