# 品牌命名与双 IP 设计规范｜v2.8

## 1. 命名提案（候选，不等同用户批准）

| 方案 | 中文主名 | 英文主名 | 品牌侧重点 | 风险与判断 |
|---|---|---|---|---|
| **A · 当前推荐** | **小怪兽成长簿** | **Monster Milestones** | 怪兽 IP + 月龄里程碑 + 记录与亲子成长 | `Milestones` 容易被理解为发展达标；必须在产品文案中明确“里程碑仅为记录和回顾，不构成发展评估” |
| B · 叙事型 | 怪兽成长记 | Monster Journey | 成长地图、故事章节、陪伴探索 | 偏故事阅读，手帐计时和健康记录的工具属性相对弱 |
| C · 保留认知型 | 养小怪兽 | Little Monster Journal | 沿用现有中文名与怪兽人格，英文补充手帐属性 | 中英文不是逐词对应；如需国际一致性应核查受众理解 |

**关键准则**：中文与英文都是面向各自语言环境的品牌表达，无需强行逐字翻译；名称应易读、便于 App 图标下展示、与育儿内容对应，并为 0–3 岁之外的内容扩展留空间。

推荐主品牌呈现：`小怪兽成长簿`，英文小字 `Monster Milestones`；功能副标：`0–3 岁育儿记录与成长陪伴`；国际化解释性副标候选：`Early Years Journal & Activities`。品牌短句 `陪孩子慢慢长大` 仅用于欢迎页、品牌页与少数章节封面，不是每张卡片的重复文案。

**商店约束**：iOS/Google Play 的展示长度、名称冲突、商标、域名、社媒句柄和搜索混淆度必须在最终确认前逐项核查，本文件**未进行可注册性/商标检索**。不可声称任一名称已可注册、已可上架。

## 2. 命名涉及的全部触点（审批后才执行）

- 直接显示：启动页、登录/首次须知、顶部标题、设置关于、通知、分享卡片、导出文件名、备份恢复说明、家人协作文案、支持/反馈、隐私及许可说明。
- 平台：iOS `CFBundleDisplayName` 与商店元数据、Android `app_name` 与 Play 元数据、桌面短名称、快捷方式、动态组件、小组件展示及通知渠道名称。
- 外部：官网页面、图标、隐私政策中运营主体与产品名称、支持邮箱签名、商店截屏、品牌语言简表。
- **不能因品牌改名而迁移** package/applicationId、iOS Bundle ID、数据库路径、用户数据主键、URL scheme、存储前缀、备份格式。若确需改变这些标识，必须独立列迁移与回滚方案，经批准后实施。

## 3. 双小怪兽 IP，不降低数量、不擅自改造

现有形象暂以 `双眼款`、`独眼款` 表示，实际素材/命名由仓库确认。此前草稿曾混用“圆眼款”等叫法；此处只使用可从现有素材辨识的临时名称。现有形象切换、深浅模式、四个底部 IP Tab、绘本插画与贴纸资产全部保留。

- **主题空间**：每个角色有 `主题主色 / 辅助色 / 描边与角色轮廓 / 背景层级 / 夜间适配 / tab 小尺寸素材 / 小动效`。操作语义（如警示、成功、禁用、健康状态）两主题保持一致；两个 IP 的外观可不同，行为模型相同。
- **出场语法**：顶部封面可用完整版怪兽，Tab 用专门适配 24–32 视觉单位的小尺寸姿态（实际热区满足平台要求），贴纸用表情版，反馈用短暂局部动作。用户不要求减少怪兽密度，不能设“每页只出现一次”限制。
- **IP 绝不替代数据**：观察是否看过、活动是否做过、接种是否已记录都必须显示文字或清晰的状态图形。双怪兽切换不能改内容语义、已存数据、当前月龄、路由栈或滚动位置。
- **动效边界**：完成活动后可短暂庆祝；护理计时、输入、医疗安全内容和长阅读中应保持宁静，角色可静态存在；遵守系统减少动画选项。
- **图像尊重原画**：保持完整眼睛、耳角、头饰与关键动作；先改容器纵横比、`contain`/适配、留白与排版，未经证据不裁切替换现有素材。

## 4. 品牌决策验收包

Claude 必须提交同屏 3 组品牌排版，而非只发一个文字表：
- 应用图标下的短名 + 欢迎页主名 + 首页窄顶部栏 + 设置关于 + 商店截图预览；
- 至少两个中文字号档、一个较窄屏宽、英文版本；
- 双眼/独眼 × 浅/深主题各核对 1 组主视觉；
- 一张品牌触点清单，说明哪些名称必须等待批准。

请用户只确认 **中文主名、英文主名、短标题方案** 三项；IP 正式姓名/配色保留独立决策。未经这三项确认，Claude 应保持当前已上线名称，不阻塞其它功能精修。
