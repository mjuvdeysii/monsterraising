# Raising Monster v2.7｜组件行为、状态矩阵与界面文案

这是对主设计规范的**实施级补充**。所有尺寸均为项目候选值，必须与代码、平台控件和真实字体缩放核对。

## 1. 一级导航：四个 IP Tab

| 要素 | 设计建议 | 行为与验收 |
|---|---|---|
| 今天 | 现有小怪兽/道具形象 + “今天” | 返回时保留上次滚动，若多次点击当前 Tab 的回顶行为需按已有产品约定确认 |
| 手帐 | 小怪兽表现记录/护理功能 + “手帐” | 正在计时不受切 Tab 影响；未开启时保留原说明态 |
| 目录 | 小怪兽/图书形象 + “目录” | 保留浏览月龄、全部月份 Sheet 关闭状态、搜索与筛选 |
| 记录 | 小怪兽/贴纸或相册形象 + “记录” | 回到最近访问的记录区域，不跳到贴纸册顶部 |

- **不做强制 IP 减量。** 未选中态仍可见角色关键特征；可通过轻描边、淡底和字号形成主次，不直接抹灰角色至难以辨认。
- 每个 Tab：显示角色图（建议在实际尺寸约 22–28 逻辑单位内试样）+ 中文短标签；整个命中区满足 Android 48dp / iOS 推荐 44pt。实际图片文件必须透明留白合理，眼睛、头饰、拿着的小道具在真机上能辨认。
- 选中态：语义 label、accessibility selected、形状/背景/文字对比同时更新，不靠 IP 表情一个变化承担全部区分；没有自动连续跳动。
- iOS Tab 栈和 Android Back 栈按各自平台处理，同一张 WebView UI 也须在原生外壳中实现真实系统导航行为。

## 2. “今天可以做”推荐卡

| 区块 | 最多显示什么 | 排版/交互 |
|---|---|---|
| 卡片眉题 | 今天可以做、活动领域 | 与标题明显分层，避免再显示三个同意义标题 |
| 绘本插画 | 本活动或本月主图 | 原比例完整呈现；渲染文字与图片分离 |
| 标题 | 一条清楚的活动名称 | 中文最多 2–3 行，允许自然换行，不三列并排 |
| 一句话概述 | 这个活动的家长操作 | 用动作动词与材料说明，避免临床术语堆砌 |
| 安全提示 | 适用时可见的风险 | 不用浅灰角标或仅色彩表示，给出具体限制 |
| 主 CTA | 查看做法（或确认的实际动作） | 点击进入详情，不能因为“看了做法”自动记为做过 |
| 次动作 | 换一个 / 今天先跳过 | 改推荐但不改变完成计数，不制造负面打卡状态 |

- 如果图片迟到，预留图片容器、保持卡片主 CTA 的位置稳定。
- 系统大字时先把按钮移到独占一行，而不是强行挤压文字。
- 如果安全信息比较长，标题旁出现“安全提示”，详情首屏展示完整信息；有立即风险不得把全部解释藏于最末尾。

## 3. “继续上次”组件（分支优先级）

推荐优先级取决于当前真实数据：`正在运行的护理计时 > 已暂停的护理计时 > 有效的阅读锚点 > 无继续卡`。这是建议优先级，须在仓库确认产品意图。

| 真实数据情况 | 文案示例 | 入口动作 |
|---|---|---|
| 正在亲喂 | 亲喂计时中 · 左/右侧 | 回到同一计时事件 |
| 睡眠暂停 | 睡眠计时已暂停 | 打开原事件，提供继续/结束 |
| 上次阅读在第 6 月活动 | 继续阅读 · 满 6 个月 / 声音接龙 | 精确恢复章节/段落/滚动 |
| 无有效对象 | 不显示“继续” | 下一个模块自然上移 |

禁止用静态示例填充个性化信息；开始一项新活动不等于继续旧计时。

## 4. 月龄条和全部月份 Sheet

**月份条**：默认按正在浏览月龄排列最多左右各两个邻月，旁侧始终能找到 `全部月份` 和 `回到现在`（正在浏览不等于当前时）。

**全部月份 Sheet**：
- 标题“选择月龄”，说明“宝宝现在：X 月”；分段 0–3 / 3–6 / 6–9 / 9–12 / 12–18 / 18–24 / 24–30 / 30–36，交界月份只显示一次。
- “宝宝现在”和“正在看”标签可同时在一个月份上出现；仅显示真实有意义的状态，不再使用无法解释的小点。
- 焦点/键盘顺序先标题再“跳到现在”，然后月份按自然顺序；Sheet 可关闭，不因关闭而改浏览月龄。
- 触发目标月龄时立即更新“正在看”，若内容异步加载，以目标月龄为主状态；错误时给“重试”而不回滚用户选择到旧月份。
- 如果某月含接种建议、观察节点等，进入详情后按类别显示，不在月份列表里用大量五颜六色的小点编码。

## 5. 状态文案：严格使用语义词

| 用户做的事 | 成功反馈 | 反面表述（避免） | 对应数据 |
|---|---|---|---|
| 阅读一条观察清单 | 已标为看过 · 撤销 | 能力已达成 | contentReviewed |
| 实际进行一次活动 | 已记为做过 · 撤销 | 宝宝已掌握该能力 | activityPerformed |
| 写下观察事实 | 观察记录已保存 | 宝宝发育正常 | observationRecorded |
| 确认接种记录 | 已记录接种 · 2026-XX-XX | 本月全部自动完成 | healthEventConfirmed |
| 手帐本地持久化成功 | 已存到本机 | 已同步到云端（若无同步） | journalSavedLocal |
| 云同步正在排队（有云功能时） | 待同步 | 已经备份（若尚未完成） | syncPending |
| 手帐持久化失败 | 暂未保存，请重试 / 保留当前内容 | 保存成功 | saveFailed |
| 保存纪念贴纸 | 纪念已收集 | 你已经领先同龄宝宝 | stickerAwarded |

**完成百分比**：建议“本月活动 6/22 · 27%”，对应范围清楚；不要把“观察看过、活动做过、接种确认”相加产生一个含义不明的育儿任务总分。

## 6. Activity Card 与活动详情

- 活动列表卡：插画缩略图（完整比例或已确认安全裁切）/ 活动名/ 领域/ 月龄参考/ 一条重点信息/ 可见入口。展开全文才出现操作步骤，不要在横向滑动窄卡中塞 100 字。
- 详情信息顺序：`做什么 → 需要什么 → 怎么做 → 观察什么 → 安全提示 → 记录`；涉及安全风险时安全提示提前至操作之前，页面顶部有明确可见的提醒。
- “记为本月做过”按钮是一个真实写入操作，不应放在阅读入口上。完成后按钮变为“已记为做过”，并有“撤销/更正”；计数立即一致且失败会回退或提示。
- 返回时恢复此前列表月份、分类筛选和滚动，不能自动滚回卡片第一项。

## 7. 手帐 Quick Action、计时与保存提示

| 状态 | 可用动作 | 必须呈现的反馈 |
|---|---|---|
| 空闲 idle | 开始新计时/快速记 | 输入热区明显，禁用不相关按钮 |
| 运行 running | 暂停、结束、切换计时侧（按功能） | 计时数值 + 事件类型 + 当前侧/时间 |
| 已暂停 paused | 继续、结束、取消/删除（谨慎） | “已暂停”文字，不只用灰色 |
| 保存中 saving | 等待当前写入、防二次结束 | 清晰状态，不锁死返回/草稿 |
| 已保存 saved | 查看、编辑、重记 | “已存本机”只有持久化成功才出现 |
| 需要复核 needs_review | 编辑开始/结束时间、确认 | 明确为何需要核对；不虚构时长 |
| 失败 error | 重试/保留草稿 | 不丢文字、照片和原计时数据 |

系统返回时不得结束正在运行的计时；对不确定的恢复数据不应默默确认为精准的护理时间。

## 8. 动效空间语义

| 元素 | 用户动作 | 反馈/动效 | 取消或重复 |
|---|---|---|---|
| 月龄标签 | 点月份 | 选中框即时变化，内容短切换 | 新点选立即中断上一个转场 |
| 全部月份 Sheet | 向上打开/下拉 | 跟手拖动，释放后系统吸附 | 关闭不意外选中月份 |
| 活动完成 | 记为做过 | 按钮状态、一次短怪兽开心动作 | 撤销立即更正状态；重复不写第二条 |
| 贴纸获得 | 完成有意义的纪念条件 | 贴纸轻盖章，不压过说明 | Reduce Motion 下直接展示结果 |
| 图片滚动加载 | 瀑布/普通列表 | 预留尺寸、尽量低成本渐显 | 不因图像到达移动阅读内容 |
| 计时按钮 | 按下、暂停、继续 | 即时按压/文字状态，无循环大动效 | 双击不得产生两个事件 |

## 9. 空态、失败态、离线态示例

- **月龄内容为空**：“这个月暂时没有可展示的活动” + “查看全部活动”；不要写“宝宝还没有学会”。
- **手帐未开启**：“开启后可记录喂养、睡眠和每日护理” + “开启育儿手帐”，并保留“暂不使用”。
- **本地保存失败**：“这条记录暂未保存。内容仍保留在当前页面。” + “重试保存”。
- **离线**：“当前处于离线状态。已保存的内容仍可查看；新记录保存在本机。”仅在确实已持久化时使用后半句。
- **月龄切换加载失败**：“满 X 个月的内容加载失败” + “重试”，标题仍显示用户选择的 X，不跳回先前月份。
- **接种/儿保未确认**：“尚未填写实际记录”，不要默认“未接种”或“漏打”。

## 10. 本地语言与品牌命名

界面简体中文优先，英文仅用于 App 品牌或用户确有语言设置的场景。应用英文名尚未统一（Raising Monster / Monster Raising），不得只改标题却遗漏分享页、导出、设置、通知与应用商店元数据。最终确定后建立唯一的 i18n 品牌 token 执行替换和回归。

文案采用具体、客观、完整的陈述句；避免夸张的成长评价、自问自答、压力式打卡、能力判定与医学暗示。
